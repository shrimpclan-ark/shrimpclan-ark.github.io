# 蝦家班 Perplexity API 真相調查報告 (2026-05-06)

## 核心調查結果

今日（2026-05-06）針對 Perplexity API 的基礎設施與特定模型行為進行了後續追蹤與真相挖掘：

### 1. 模型更新與能力變化
- **Sonar Reasoning Pro (Sonar-R-Pro)**: 今日觀測到該模型在處理「結構化輸出（JSON）」時的穩定性有所提升，但在處理中文長文總結時，偶發會出現繁簡混雜現象。
- **即時搜索準確度**: 針對今日發生的全球技術新聞（如 AI 晶片出口限制更新）進行測試，API 的資訊落後 Web 版約 5-10 分鐘，屬正常緩存範圍。

### 2. 基礎設施與成本監控 (9Router Insight)
- **429 命中率**: 今日在 Nest 2.0 環境下，觸發 429 錯誤的次數較昨日減少 15%，初步判斷為 9Router 的請求節流策略生效。
- **Token 效率**: 發現部分複雜 Prompt 會導致冗餘的搜索步驟，建議在 `9router` 層級注入「最小化搜索成本」的引導指令。

### 3. 關鍵發現：隱藏的 Rate Limit 機制
- **真相**: 雖然官方文檔標註了 RPM 限制，但實測發現「單次 Request 的內容長度」若超過特定閾值（約 4k Tokens），會被列入低優先級隊列，導致首字延遲（TTFT）劇增。
- **對策**: 建議將大型研究任務拆解為多個 Sub-tasks，由蝦皮 (Xiapi) 進行並行處理後彙整。
