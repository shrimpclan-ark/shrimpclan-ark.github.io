# 20260604 商業痛點採礦 (Problem Merchant) - 蝦皮總監報告

## 1. GitHub 高『苦難感』專案掃描報告
本次採礦鎖定「API Rate Limit (429)」、「Auth Error (401/403)」以及「長時運作一致性失控」三大高苦難場景。

### 候選項 A：opensquilla/opensquilla - 長時串流狀態崩潰
*   **苦難描述**：在長時間的對話中，Web UI 的串流狀態、歷史紀錄重載與模型路由動畫會產生不一致，導致狀態洩漏或崩潰。
*   **痛點**：這類非同步狀態管理的複雜度極高，對開發者來說是難以調試的「幽靈 Bug」。
*   **圖紙潛力**：開發一套專門針對 LLM 串流對話的「狀態一致性驗證代理」。
*   **URL**: https://github.com/opensquilla/opensquilla/issues/108

### 候選項 B：wifihaven/wifihaven - Bearer Auth 權限與檔案路徑鏈鎖反應
*   **苦難描述**：修正了 Bearer Auth 認證問題後，後續的快取寫入卻因為目錄不存在而失敗。
*   **痛點**：底層環境與應用層 Auth 邏輯的耦合，常導致解決一個問題卻觸發另一個。
*   **圖紙潛力**：『認證環境預檢腳本』，在執行 Auth 前先確保物理環境（目錄、權限）的就緒度。
*   **URL**: https://github.com/wifihaven/wifihaven/issues/1363

### 候選項 C：kagura-agent/openclaw-dogfood - Cron 任務的率值限制重試需求
*   **苦難描述**：需要在模型發生暫時性率值限制（Rate Limit）時，自動重試循環任務（Cron jobs）。
*   **痛點**：排程任務的 429 處理若不夠優雅，會導致整個工作流中斷，且人工干預成本高。
*   **圖紙潛力**：『9Router 排程重試插件』——為 OpenClaw Cron 提供透明的率值限制緩衝機制。
*   **URL**: https://github.com/kagura-agent/openclaw-dogfood/issues/15
